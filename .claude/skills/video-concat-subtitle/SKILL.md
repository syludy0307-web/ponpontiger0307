# 動画の連結・タイトル・文字起こし・字幕

このスキルは、あるユーザーと何本も動画を仕上げる中で固まった「完成形」と
「つまずいた所の対処法」をまとめたものです。

ユーザーは細かい指示を出しません。依頼はたいてい次のような一言です。

> これを番号順に連結お願いします
> タイトル「〇〇」
> 文字おこしもおねがいします

この一言で、下の「完成形」どおりの動画・文字起こし・字幕が揃って出てくることを期待しています。
過去の流れでは、文字起こしだけ頼んだ場合でも毎回字幕入りの動画を欲しがり、
「次から一発で送ってきていいよ」と言われています。そこで次のように決めています。
- **動画を作る依頼**（連結する・タイトルを入れる、のどちらかがある）で文字起こしも頼まれたら、
  字幕の焼き込みまでやって一式で納品する。1本だけ・タイトルだけでも同じ（字幕が要らないときはそう言われます）
- **「タイトル無し」と断ってある**依頼は、いつもの一式からタイトルだけを抜く合図。字幕入りの動画まで作る
  （`render.py` に `--title` を付けない。lines.json の `title` は `"タイトルなし"`）
- **タイトルの指定が無く、「タイトル無し」とも言われていない**（「これもぜひ」だけ）ときは、書き忘れのことが
  多い。文字起こしの調査（数分かかる）を先に走らせながら、タイトルを聞く。書き出しの前に答えが来ればよい
- **文字起こしだけ**の依頼（動画の加工を頼まれていない。「タイトル無しで文字おこしのみ」のように
  **「のみ」「だけ」**と言われた場合も）でも、字幕を焼き込んだ動画まで作り、txt・srt と
  **一緒に最初から送る**。タイトルの指定が無ければタイトルなしで作る（`--title` を付けない）。
  以前は txt と srt だけを渡していたが、3回続けて直後に「字幕を焼いた動画をください」と頼まれ、
  「次から一発で送ってきていいよ」と言われた

ユーザーは日本語で話します。返事も日本語で、専門用語はかみ砕いてください。

## 完成形（ハウススタイル）

| 項目 | 内容 |
|---|---|
| 連結 | ファイル名の番号順（001→002→003）。アップロード順・表示順ではない |
| タイトル | 画面上部・冒頭5秒。白文字＋濃いフチ＋影（Noto Sans CJK JP Bold）。上からスライドインして少し行き過ぎて戻る → 静止 → 最後の0.5秒で上に抜けながらフェードアウト |
| 字幕 | 画面下部・太字・濃いフチと影・0.15秒フェード。**女性＝ピンク #FF5FAF、男性＝金 #FFC24A** |
| 心の声 | 字幕を（ ）で囲む |
| 画質 | 解像度は素材のまま。H.264（CRF18）＋AAC 192kbps の mp4。エンコードは1回だけ |
| 納品物 | `<名前>_final.mp4`、`transcript_<名前>.txt`（時刻・話者・補足つき）、`transcript_<名前>.srt` |
| 納品先 | ユーザーのデスクトップ |

`<名前>` はタイトルのローマ字（例：嘘つき → `usotsuki`）。タイトルが無いときは、内容を表す短い言葉の
ローマ字にして（例：「〜ちゃんのお友達が出るみたい」→ `otomodachi`）、報告でその名前にしたと伝えます。
聞き取りに自信のない固有名詞はファイル名に使わないでください（間違っていたら名前ごと直すことになります）。

サイズ・位置・アニメーションの式などの細部はすべて `scripts/` に入っていて、スクリプトを
使えば自動でこの見た目になります。ffmpeg のコマンドを自前で組み直さないでください。
毎回同じ仕上がりになり、過去に踏んだ罠（後述）も避けられるからです。

## 進め方

1. 準備（環境チェック・作業フォルダ・素材のコピー・並び順の決定）
2. 文字起こしの調査（`analyze.py scan`）
3. 気になる所を詰める（`analyze.py window`）
4. 話者を決める（`frames.py` で画を見る）
5. セリフ一覧 `lines.json` を書いて字幕を作る（`make_subs.py`）
6. 書き出しと検品（`render.py` → `review.jpg` を目で見る）
7. 文字起こしの「補足」を書き、デスクトップに納品（`deliver.py`）して報告
8. 片付け（頼まれたときだけ）

以下、`<スキル>` はこのスキルのフォルダ（読み込み時に表示される Base directory）、
`python` は `setup_check.py` が「準備OK」になった Python を指します。

### 1. 準備

```
python <スキル>/scripts/setup_check.py
```
足りないものがあれば OS ごとの入れ方が表示されます。ユーザーに断ってから入れてください。
詳しい手順とエラーの対処は `references/desktop-setup.md`。
初回は Whisper のモデル（約3GB）のダウンロードがあるので、時間がかかることを先に伝えます。

作業フォルダを作り、**素材はそこへコピーして使います**（名前は変えなくてかまいません）。
```
~/video-work/<名前>/          （Windows なら %USERPROFILE%\video-work\<名前>\）
```
手元の PC では、ユーザーが指定した動画は本人の**元ファイル**です。加工・移動・削除はしないでください。
このスキルが生まれたクラウド環境ではアップロードのコピーだったので消せましたが、
手元ではそれが唯一の原本かもしれません。

並び順は**ファイル名の番号**で決めます（拡張子の直前にある数字。`A.mov`・`B.mov` のように
アルファベット1文字なら ABC 順。`scripts/common.py` の `clip_number` と同じ考え方）。
アップロードやドラッグの順番は当てになりません
（「003, 001, 002」の順で届いたことがあります）。以降のスクリプトには、クリップをこの番号順に
並べて渡します（渡した順に連結されます）。決めた順番は最初にユーザーへ一言伝え、
番号が読み取れないファイルがあれば順番を聞きます。1本だけのときは並べる必要はなく、
スクリプトにもその1本だけを渡せば連結なしで同じように仕上がります。

### 2. 文字起こしの調査

```
python <スキル>/scripts/analyze.py scan 001.mov 002.mov 003.mov --work <作業フォルダ>
```
数分かかります。1回の認識だけでは何度も取りこぼしが起きたので、このツールは5通りの聞き方を
一度にやって並べて見せます。

- **A. 連結・VADあり** — 基準にする
- **B. 連結・VADなし** — A が2つの発話を1つに合体させ、片方を消すことがある。B にしか無い発話は要注意
- **C. クリップごと** — クリップの境目をまたいだ取り違えを防ぐ（複数の行を1つにまとめがち）
- **D. 音があるのに文字が無い区間を言語自動判別で聞き直し** — 日本語指定のままだと英語のセリフが丸ごと消える
- **E. 語と語の間が大きく空いている所を前後に分けて聞き直し** — 1語だけ数秒前に取り残される「ずれ」がよく起きる

最後の「まとめ」を起点に、上の各節を見て判断します。

- **幻聴**：無音・BGM・効果音の区間で Whisper は「ご視聴ありがとうございました」
  「Thanks for watching!」「おわり」、各国語の字幕クレジット、絵文字だけの結果などを出します。
  先頭の語の信頼度が極端に低い（0.35未満）、言語判定が不確か、動画の長さを超えた時刻、が目印です。
  ツールが「⚠幻聴の疑い」を付けますが、最終判断は内容と音量の山を見て自分でします
- **B にだけある発話** → 取りこぼしの可能性。window で聞き直して確かめる。曲や BGM が大きい動画では、
  A が何も出さず B だけがセリフを拾うことがある
- **ユーザーがセリフの場所を教えてくれた**とき（「2だけ最後にセリフあり」）は、それを信じてその区間を
  重点的に聞き直す。曲・BGM だけの区間は字幕にしない
- **D の実発話らしきもの**（日本語以外も含む）→ 字幕に入れる。セリフに「英語わからない」のような
  手がかりがあるときは特に疑う。「直前の〜の語尾かも」と出た区間は、セリフの言い終わりを拾っただけ。
  ただし前の行の終わりがその区間より0.5秒以上早いなら、終わりを声の切れ目まで延ばす
  （「ありがとうございます」が 24.14秒で切れていて、実際の声は 24.9秒まで続いていたことがある）
- **笑い声・歓声・悲鳴・相づち・うなり声**（あははは・おー・キャッ・イェーイ）→ セリフではないので字幕にしない。
  txt の補足には時刻と一緒に書く。ただし驚きや聞き返しの「え？」のように、はっきり言葉として返しているものは
  セリフとして字幕にする（悪だくみ・また足? の「え？」）

時刻の決め方（「まとめ」の ※ にそのまま使える時刻が出ます）：
- **E の空白** → ツールが出す「音の立ち上がり ≈ ○秒」を開始時刻にする。取り残された1語はたいてい後ろの発話の一部
- **長すぎる語**（1語が0.9秒以上）→ ツールが前の間の長さを出す。**1秒以上なら**そこで行を分け、
  後ろの行を「音の立ち上がり」から始める。1秒未満、または「頭から声が続いている」と出たら1行のままでよい
- **前の行とくっついている**（前の行の終わり＝この行の始まり）→ Whisper が境目を寄せただけのことが多い。
  「無音のあと ○秒から声」と出たら、その時刻を開始にする（そのままだと、字幕が前の人の場面の無音に
  1秒近く早く出てしまったことがある）
- **長い行**（5秒以上か28文字以上）→ A が別々の文を1行にまとめていることがある（3つの文が0〜7秒の1行に
  なったことがある）。その行の「行の途中 ○–○ 秒が無音で、B もここで区切っている」を見て、
  **前で文が言い終わっていれば**（「元気？」「〜みたい」など）そこで行を分け、後ろの行はそこに出ている時刻から始める。
  「はぁ、」「お姉さん、」のような呼びかけ・言いかけの後の間なら1行のまま「、」にする
- **行の途中に間（B は区切っていない）** → ふつうは1行のまま。読点「、」を入れる場所の目安になる
- **それ以外の行は、開始・終了とも A の時刻のまま**でよい。Whisper は0.3秒ほど早めに出がちですが、
  開始が少し早いぶんには問題にならず、終了は後ろに0.3秒の余白が自動で付くので足ります。
  音量から推定し直すと、ため息のような小さな声で始まる行で遅れる方向に外れます

「音の立ち上がり」は声の大きさで判定していて、息を吸う音はふつう拾いませんが、念のため
その時刻から少し後ろを window で聞き直すと確実です。

### 3. 気になる所を詰める

```
python <スキル>/scripts/analyze.py window <作業フォルダ>/audio_concat.wav 開始 終了 [開始 終了 ...] [オプション]
```
モデルの読み込みに毎回20〜40秒かかるので、聞き直したい区間は**まとめて1回で渡します**。
語ごとに開始・終了の時刻と信頼度が出ます。
- 開始時刻を詰める：`--lang ja`。区間を切り出すと先頭の語がその開始に張り付きやすく、そのときは
  「音の立ち上がり」が表示されます。使うのは上の「時刻の決め方」でずれを指摘された行だけです
- 日本語以外かも：`--lang auto`（短い日本語が別の言語に誤判定されることもあるので `--lang ja` の結果とも比べる）
- 意味の通らない語（固有名詞・造語かも）：`--models large-v3,large-v2,medium`、`--hotwords 候補の語`、
  `--prompt "場面の説明"`（large-v2 と medium は初回ダウンロードあり）

意味の通らない語の扱い：
- **モデルどうしで一致し信頼度も高い** → 聞こえたとおりに書き、報告で「固有名詞かもしれない」と添える。
  名前の漢字は一致していても当て字のことがあるので、読みも添える（3つとも「脇草ちゃん」だったが、
  正しくは「脇臭ちゃん」だった）
- **モデルで割れる** → 読み（音）が揃っているか確かめ、文脈で一番自然な表記を選び、報告で候補を挙げて確認をお願いする

どちらでも、黙って意味の通る別の言葉に置き換えないでください。ユーザーは作品の中身を
知っているので、聞こえたまま＋注記のほうがずっと役に立ちます（実例は `references/lessons.md` の5）。

### 4. 話者を決める

字幕の色は話者で変わるので、全行の話者を決めます。決め手は**画**です。

```
python <スキル>/scripts/frames.py --clips 001.mov 002.mov 003.mov --at 2.1 5.0 7.6 \
    --labels "1 ねえ、どこ行ってたの" "2 ちょっとコンビニまで" "3 また嘘ついてる" --out <作業フォルダ>/who.jpg
```
各セリフの途中の時刻を並べ、Read ツールで開いて見ます。
- その瞬間に**1人しか映っていない**なら、ほぼその人。ただし映っている人の**口が閉じたまま**なら、
  画面の外にいる相手のセリフ（肩越しの構図などでよくある）
- **口が開いている・身振りしている**人
- 顔のアップで口を閉じて笑う場面の独り言は心の声のことが多い（→ `aside`）

口元が小さくて見えにくいときは、拡大して細かく並べます。
```
python <スキル>/scripts/frames.py --clips 001.mov --range 7.6 9.0 --step 0.2 \
    --crop 0.35,0.1,0.55,0.45 --out <作業フォルダ>/mouth.jpg
```
（`--crop` は 左上X,左上Y,幅,高さ を画面に対する割合で指定）

画と会話の流れ（問い詰める側／答える側、「私」「お姉さん」などの呼び方）が揃えば確定です。
**それでも決めきれない行は、書き出す前にユーザーに聞いてください。** 書き出した後で直すより
ずっと安く済みます（0.7秒しかない「ゾンビか」を女性と判断して外し、指摘を受けたことがあります）。

声の高さ（F0）を自前で推定して判定するのはやめてください。試した結果、男性の声を2倍に、
女性の声を半分に見誤るオクターブ誤りが何度も起き、女性が1人で映っている場面のセリフが
「男性域」と出たこともあります。

### 5. セリフ一覧を書いて字幕を作る

`<作業フォルダ>/lines.json` を書きます（下の中身は書き方の例です）。
```json
{
  "title": "嘘つき",
  "lines": [
    {"start": 1.20, "end": 3.10, "speaker": "female", "text": "ねえ、どこ行ってたの？"},
    {"start": 3.80, "end": 6.40, "speaker": "male", "text": "ちょっとコンビニまで行ってたんだけど、\n混んでてさ"},
    {"start": 7.05, "end": 8.20, "speaker": "female", "text": "また嘘ついてる", "aside": true},
    {"start": 9.00, "end": 10.60, "speaker": "male", "text": "What are you doing?", "label": "男性・英語"}
  ]
}
```
- `start` / `end` は**発話そのもの**の時刻（連結後の通し時刻）。字幕の前後の余白・重なりの回避・
  短すぎる行の延長はスクリプトがやります
- `speaker` は `female`（ピンク）/ `male`（金）/ `other`（白）
- 長いセリフは意味の切れ目に `\n` を入れる（入れなければ、はみ出すときだけ句読点で自動改行）
- 文の途中に1秒以上の間があれば2行に分ける
- 言いよどみ・言い直しは聞こえたとおりに書く（例：「それは…それはちょっと」）
- `aside: true` は心の声。字幕に（ ）が自動で付くので、text には（ ）を書かない
- `label` は txt に書く話者の表記を変えたいとき（「男性・英語」など）

表記の決まり（これまでの完成品と揃える）：
- 問いかけの抑揚なら「？」を付ける（全角）。句点「。」は付けない
- はっきり弾んだ言い方（「久しぶり！」のようなあいさつ・呼びかけ）は「！」（全角）を付けてよい
- 読点「、」は息継ぎ・意味の切れ目に。Whisper の句読点は位置がおかしいことがあるので聞いて直す
- 言いよどみ・間は「…」
- 漢字とかなは一般的な書き方でよい（Whisper の出力のままで問題なければそれで）。
  ふつうの言葉はタイトルの表記（ひらがな等）に合わせる必要はない。タイトルはユーザーの指定どおりにする
- ただし**タイトルと同じ名前**（キャラ名・チャンネル名など）がセリフに出たら、タイトルの表記に揃える。
  Whisper は同じ名前を「柴猫ガール／シバネコガール／しばねこガール」のようにばらばらに書くことがある
- 同じ登場人物が何本もの動画に出てくる。ユーザーが決めた（直した）名前は、別の動画でもその表記にする：
  **シバネコガール**（タイトルで指定）、**脇臭ちゃん**（わきくさちゃん。Whisper は「脇草ちゃん」と書く）、
  **ミライ**（Whisper は「未来」と書く）。新しく直されたらここに足す

```
python <スキル>/scripts/make_subs.py <作業フォルダ>/lines.json --clips 001.mov 002.mov 003.mov \
    --name usotsuki --work <作業フォルダ>
```
自動改行や文字の縮小をした行は表示されます。不自然なら lines.json を直して作り直します。

### 6. 書き出しと検品

```
python <スキル>/scripts/render.py --clips 001.mov 002.mov 003.mov --title "嘘つき" \
    --ass <作業フォルダ>/subs.ass --work <作業フォルダ> --out <作業フォルダ>/usotsuki_final.mp4
```
「タイトル無し」の依頼や、タイトルの指定が無い文字起こしだけの依頼なら、`--title` を付けずに
実行します（字幕だけが入ります）。
規格の違うクリップ（yuv420p と yuv444p、AAC と PCM、解像度違い）が混ざっていても1回の
エンコードでまとめます。終わると尺・フレーム数・デコードエラー・音量を自動で検品し、
`review.jpg`（タイトルと各字幕の場面を並べた画像）を作ります。

**review.jpg は必ず Read で開いて目で確認します。** 見る点：タイトルが上部中央で読めるか、
字幕の色が話者どおりか、改行が自然か、顔や大事なものに字幕が被っていないか。
検品に「要確認」が出たら、原因を調べてから納品します。

### 7. 納品と報告

1. `transcript_<名前>.txt` の最後の「補足」を書き足す：
   - 字幕にしなかった音（笑い声・歓声・効果音）とその時刻
   - 幻聴として除外したもの（「ご視聴ありがとうございました」など）と、そう判断した理由
   - 話者の決め手（画・会話の流れ）
   - 固有名詞など、ユーザーに確かめてほしい点
2. デスクトップに納品する（同名のファイルがあっても上書きせず別名で置く）
   ```
   python <スキル>/scripts/deliver.py <作業フォルダ>/usotsuki_final.mp4 \
       <作業フォルダ>/transcript_usotsuki.txt <作業フォルダ>/transcript_usotsuki.srt
   ```
   デスクトップが見つからないと言われたら、ユーザーに置き場所を聞いて `--to <フォルダ>` を付けます。
   デスクトップの無い環境（クラウド版など）では、ファイル送付のツールでユーザーに渡します。
3. ユーザーに報告する。短く、でも判断したことは隠さずに：
   - 並べた順番と長さ
   - 文字起こしの全行（時刻と色）をコードブロックで
   - 確かめてほしい点（固有名詞・自信のない話者）を先に、はっきり
   - 取りこぼしを見つけた・幻聴を除いたなど、気をつけた点を2〜3行
   - どこに置いたか

### 8. 片付け

「使ったものは消してお掃除して」と頼まれることがあります。消してよいのは**作業フォルダの中身だけ**です。
元の動画は、はっきり「元の動画も消して」と言われない限り消しません。

また、**ユーザーが完成品を確認し終える前に作業フォルダを消さないでください。**
納品後に「この行は男性だった」と直しが入ったとき、作業フォルダ（lines.json・素材のコピー）が
残っていれば数分で作り直せます。以前、消した直後に直しが入り、作り直せなかったことがあります。
消す前に何を消すか一覧を見せ、消した後は消したものと空いた容量を伝えます。

## 声の差し替え（「この声を変えて」と音声ファイルが届いたとき）

納品した動画のセリフについて「アニメ声すぎるから変えて」と、ElevenLabs などで作った音声（mp3）が
届くことがあります。送り返された完成品ではなく、**作業フォルダの元の素材から作り直します**
（映像を2回エンコードしないため。作業フォルダが無いときだけ、届いた完成品を素材にする）。

1. 新しい音声を作業フォルダにコピーし、16kHz の wav にして `analyze.py window` で文字起こしする。
   言っている言葉と、声の長さを確かめる（ユーザーのメッセージの言い回しと語順が違うことがある。
   字幕の言葉は音声のとおりにし、表記・句読点はユーザーの書き方に寄せる）
2. 差し替えた音声を作る
   ```
   python <スキル>/scripts/replace_voice.py --clips 001.mov 002.mov --voice new.mp3 \
       --at 新しい声の話し始め --mute 元のセリフの始め 終わり --work <作業フォルダ>/voice
   ```
   - `--mute` は元のセリフの範囲（声の出始めの少し前〜言い終わり。最後のセリフなら動画の終わりまで）
   - `--at` は元のセリフの話し始めあたり。新しい声が長くて動画の終わりに入らないときは、入る時刻を
     ツールが教えるので、その範囲で早める（口が動き始める所より大きく前にしない）
   - 音量は消した元のセリフに合わせて -1 dB（「少しだけ下げて」）。大きく／小さくと言われたら `--offset-db`。
     元の声と同じ場所で鳴っているように、ごく軽い響きと高音の丸めも自動で付く（`--dry` で付けない）
3. lines.json のそのセリフを、新しい声の言葉と時刻（ツールが最後に表示する）に直して `make_subs.py`
4. `render.py` に `--audio <作業フォルダ>/voice/voice_mix.wav` を付けて書き出す（タイトル・字幕はいつもどおり）
5. 完成品のその区間を文字起こしして新しい声になっているか、それ以外の部分の音が変わっていないかを確かめる。
   補足には、差し替えたこと・置いた時刻・音量の調整を書く
